# PR 评审模式

目标是单个 PR 时的五阶段映射。issue 清单模式不读本文件。

## 1. 同步

- 读 PR 本体与 diff（`pull_request_read` 的 get / get_files）、关联 issue、全部评论与既有 review。
- `get_me` 确认身份，身份决定「处理」的含义：PR 作者 → 落实意见、推送修订、回帖；仓库维护者 → 核验证据、做合并决策；无关第三方 → 只能评论。
- 本地已有克隆时，先核对分支与 PR head sha 一致。

## 2. 分诊

- 有评审意见：逐条摘成可执行修改点；有歧义先回帖问清，再动手。
- 无评审意见：把 PR 正文声称的证据当主张验证——在 PR 分支复跑（测试子集、typecheck），基线不符先报告。

## 3. 实现

- 意见即规格：逐条落实，意见没点名的一律保持原样。
- 意见要求删测试时，按仓库测试文化决定是否补可击杀的替代钉子（有 mutation-audit 约定的仓库要补）。
- 修订并入单个 commit 再推，评审历史保持可读。

## 4. 审查

- Spec 轴 = 评审意见；Standards 轴 = 目标仓库的规范文档（规则见根 SKILL.md 第 4 阶段）。
- 审查揪出的缺陷修复后复验：受影响测试加全量门禁。

## 5. 回写

- 顺序：推修订 → 范围收窄使 PR 标题或正文失实时同步更新 → 回帖逐条对应意见附证据。
- 语气与证据规则见根 SKILL.md 第 5 阶段。
